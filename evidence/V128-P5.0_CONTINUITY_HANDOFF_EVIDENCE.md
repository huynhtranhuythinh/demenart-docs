## 3. P5 Problem Statement Evidence

The current product now has:

- scheduled lesson sessions;
- teacher operational surfaces;
- teacher report/closeout actions;
- parent-facing session outcomes;
- school administrative writers.

These capabilities create a dependency on an unambiguous answer to:

> **Which teacher is responsible for which class/session, and what is the authoritative source of that responsibility?**

No P5.0 evidence proves that the current schema already answers this correctly.

Therefore an audit-first gate is required.

---

## 4. Semantic Risks Recorded

The following are explicitly recognized risks:

1. treating teacher account access as assignment;
2. treating mutation actor as assigned teacher;
3. treating session creator as teacher responsibility;
4. rewriting historical teacher attribution after class reassignment;
5. lacking a substitute/override representation;
6. UI fallback chains becoming accidental business semantics;
7. granting assignment mutation authority without explicit governance;
8. showing parents a teacher derived from a non-authoritative field.

---

## 5. Frozen P5.0 Invariants

- Assignment ≠ access.
- Assignment ≠ actor.
- Class assignment ≠ necessarily session assignment.
- Current assignment ≠ automatic historical rewrite.
- Substitute coverage must be representable if required by product reality.
- Unknown assignment is allowed until explicitly established.
- Display projection must be deterministic.
- Mutation authority must be explicit and server-enforced.
- P5.0 grants no build authorization.
